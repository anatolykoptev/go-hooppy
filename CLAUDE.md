# CLAUDE.md

Notes for coding agents working in go-hooppy: a Go client library, the `hooppy` CLI and the
`hooppy-mcp` MCP server for the Hooppy social-media posting API. The undocumented parts of that
API were discovered by recording live calls, so tests and fixtures are the memory of what the API
really does. Every document is indexed in [docs/INDEX.md](docs/INDEX.md).

## Layout

- Root package `hooppy`: the client (`client.go`, `posts.go`, `projects.go`, `schedule_slots.go`,
  `posts_search.go`, `doctor.go`, ...), `endpoints.go` (base URL, source ids), `types.go`.
- `ops/`: the shared operation layer used by both surfaces, with `ops.Registry` and the input
  structs that carry `json`, `jsonschema`, `flag` and `flagusage` tags. See "The ops layer" in
  [README.md](README.md).
- `cmd/hooppy` (CLI) and `cmd/hooppy-mcp` (MCP server, transport from go-mcpserver).
- `internal/apicov`: derives the API-coverage table from `openapi.yaml` and the code.
- `openapi.yaml`: generated by `scripts/fetch_api_docs.py`; `testdata/live/`: recorded fixtures.
- `scripts/`: stdlib-only Python helpers and their tests.

## Gate

CI (`.github/workflows/preflight.yml`) runs `make preflight` on `ubuntu-24.04-arm`:

```sh
make preflight   # fmt-check, go vet ./..., go build ./..., make test, make py-test
```

`make test` is `go test -race -coverprofile=cover.out ./...` plus a core-coverage ratchet: below
65.0% the target fails. Raise the floor when coverage durably rises, never lower it. `make py-test`
runs `scripts/test_issue_open_tasks.py` and `python3 -I scripts/test_fetch_api_docs.py`. A docs-only
PR (Markdown, `docs/`, licence, templates) skips the heavy job through the `docs-scope` job in the
same workflow; that block is canonical across the fleet and compared byte for byte, so do not edit
it here. Versions come from release-please (Conventional Commits); never tag or edit
`CHANGELOG.md` by hand.

## Invariants that are easy to break

- **Create-shaped calls never retry.** GET and DELETE retry on 429/5xx; POST, create-shaped PUTs and
  uploads must not. `TestRetryPolicySweep` and `TestRetryPolicy_CreateNotRetried` pin this.
- **Fixtures are recorded, not authored.** Add or refresh `testdata/live/*` only with
  `scripts/record_fixture.py`, and never edit a fixture to make a test pass: fix the struct. See
  [CONTRIBUTING.md](CONTRIBUTING.md).
- **The README coverage table is generated.** The block between the `apicov` markers is rewritten by
  `go test -run TestCoverageTable -update-readme .`; `TestCoverageTable_ReadmeMatchesDerivation`
  fails when it is stale. Do not edit it by hand.
- **A capability belongs in `ops/`, once.** Register it in `ops.Registry` so the CLI and MCP surfaces
  stay in parity; the `TestOpsRegistry_*` tests fail otherwise.
- **Id lists accept an int array or a comma string** (`ops.IDList`); keep validation and the advertised
  MCP schema in step through `idListMiddleware`.
- **Multi-part issues use task-list checkboxes**, one box per part, ticked only when that part is
  merged; the `issue-open-tasks-guard` workflow reopens an issue closed with unticked boxes.
- **Never print or log the API token.** It comes from `HOOPPY_TOKEN` or a token file.
- **This repository is public.** No hostnames of operator machines, operator paths, account names,
  tokens or personal data in any tracked file, tests and fixtures included.
